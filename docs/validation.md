# Перевірка реалізації

Звіт актуалізовано **14 вересня 2026 року**. Робоче середовище — macOS Apple Silicon, Node.js 24, PostgreSQL 17; Docker Compose перевірено через Colima. Автоматичні тести й скриншоти використовують mock.

## Автоматичні перевірки

Останній повний прогін після відокремлення провайдерів: **78 тестів у 8 файлах — успішно**. `npm run build` і `npm run format:check` також пройдено. Тести працюють зі справжньою тимчасовою PostgreSQL та окремим файловим сховищем; платних звернень до APIMart немає.

```sh
npm test
npm run build
npm run format:check
```

| Область             | Що перевірено                                                                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Фінанси             | Конкурентний hold, недостатній баланс без створення задачі, знімок тарифу, rollback, повторні settle/release, повернення після помилок і таймауту |
| Запас +1 с          | Фактичні 4,041667 с, межа 5 с та перевищення 6 с для замовлення 4 с; у APIMart залишається `duration: 4`; старі резерви не змінюються             |
| Worker і repository | Конкурентне захоплення, fencing, прострочений lease, перезапуск, неоднозначний submit, іменовані поля переходів                                   |
| APIMart             | Розбір відповідей, 400/402/429/5xx, `Retry-After`, стабільний `Idempotency-Key` після 429 і перезапуску                                           |
| Режими та асети     | Валідація параметрів, якості й тарифів; Edit/референси; вимірювання файлів, SHA-256 кеш, ізоляція API-ключів, MOV, тимчасові посилання            |
| HTTP та події       | SSE, callback isolation, повторні/пізні події, callback під час poll, пріоритет дедлайну над cooldown, видача медіафайлів із Range                |
| Окремі процеси      | API і worker у різних Node-процесах, сповіщення через PostgreSQL, локальне відео, остаточне списання й повернення                                 |

У `tests/providers.test.ts` окремий адаптер з ID `independent` проходить API → підготовку референсу → hold → submit/poll → власний webhook → локальний MP4 → settle/release. Перевірено повтори запиту й callback, готовий референс без модерації, polling без assets/webhook, ізоляцію однакових remote task ID, помилки конфігурації та перехід зі старого обмеження БД. Підготовку APIMart через адаптер також перевірено з підставленими HTTP-відповідями, включно з часовим токеном для відео. Другий реальний платний API не підключався.

Для зміни структури також порівняно 16 варіантів React-розмітки до й після: початковий App, налаштування п’яти режимів і стани JobCard дали однаковий HTML. Об’єднаний CSS залишився незмінним. Це перевірка розмітки, а не семантики відеогенерації.

Після оновлення Docker підтверджено health, стан, SSE, Range та ізоляцію callback listener. Контрольні суми робочої бази й збережених медіафайлів до та після оновлення збіглися. Скриншоти демонструють той самий фінансовий цикл; відокремлення провайдерів не змінює його правила.

## Docker і збереження даних

На macOS Apple Silicon через Colima перевірено production- та dev-режими Compose:

- складання Dockerfile, перевірку TypeScript і Vite всередині образу;
- окремі PostgreSQL, API та worker; API працює від користувача `node`, із `WORKER_EMBEDDED=false`;
- повний mock-цикл, SSE від окремого worker та локальне відео з Range;
- однаковий job і один hold для двох запитів із тим самим ключем;
- збереження задач, балансу, ledger і MP4 після `down` та повторного `up`;
- Vite proxy, CSS HMR і перезапуск API/worker після змін вихідних файлів.

Окремо перевірялася ширина 390 px без горизонтального переповнення. Windows і Linux на інших фізичних комп’ютерах не перевірялися.

## Межі автоматичних перевірок

- Тести адаптера перевіряють передавання стабільного `Idempotency-Key`, але не доводять фактичну дедуплікацію платних POST на стороні APIMart.
- Валідація та передавання параметрів першого/останнього кадрів, Extend, аудіореференсів і розмітки реалізовані; mock не підтверджує семантичну якість результату моделі.
- Внутрішні тарифи 720p/1080p перевіряються автоматично. Для економної інтеграційної перевірки за ТЗ рекомендовано 480p і 4–5 секунд.
- Підготовка фотографій через бібліотеку та кеш перевірена на рівні застосунку; mock не відтворює модерацію провайдера.
